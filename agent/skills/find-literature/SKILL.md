# 找文献

目标：给出一批**已按摘要筛选过的论文**，让用户快速判断读哪几篇；不是 PDF 堆栈，也不是搜索结果原样罗列。

## 检索预算

- `academic_search` **总共最多 4 次**（含按标题核对文献的搜索），先宽后窄，每次换关键词或年份。
- 每批取 **20-30 条**（`limit=20~30`），服务端默认只返回带摘要的记录；用摘要做筛选，而不是逐篇下载。
- 达到 4 次后立即停止检索：用已有摘要写清单，并说明“已到检索预算，仍有缺口”。
- `paper_import` **默认 0 篇**。只有用户明确说“精读 / 下载 / 读全文 / 核对方法”，或某条关键结论仅靠摘要无法判断时，才导入，**最多 2 篇**。

## 流程

1. `project_read`：先看项目名称、研究问题、已有文件与产物，避免重复推荐。
2. 把主题拆成 2-4 组关键词。**本地库论文以英文为主，`library_search` 优先用英文单词**（如 `diffusion`、`dual-target`），中文查询通常无结果；中文只适合中文笔记或标签。本地检索最多 3 次，命中后直接进入筛选，不要再做 `library_tag` 全量盘点。
3. 本地不足时用 `academic_search`，一次取 20-30 条。默认 `openalex`；偏生物医学补 `pubmed` / `europepmc`，偏计算机/物理补 `arxiv`。需要时按年份收窄。
4. 直接在当前批次里按摘要筛选：
   - 摘要明确支撑当前问题 → 进入候选；
   - 摘要不相关 → 丢弃，不要因为标题好看而保留；
   - `hasAbstract=false`（仅题录）→ 只能作为“待核”候选，不能据此写结论。
5. 需要补缺口再做 1-2 次窄检索；**不要用 paper_import 来补信息**。本地 `library_search` 每条已返回约 700 字摘要摘录，直接用它判断相关性，**不要为了解主题逐篇 `paper_read`**；只有要核对具体结论/页码时才读。
6. 只有用户明确要求精读时才 `paper_import`（最多 2 篇），导入后用 `paper_read` 核对摘要与正文是否一致。
7. 输出一张筛选表，列：标题、年份、来源、**基于摘要的一句话相关性**、paperId（已有/新导入要分清）。摘要缺失的条目单列并标注“仅题录，未纳入判断”。最后给 1-2 个仍缺证据的方向。

## 约束

- 不要为了凑数推荐不相关的论文；宁可少而准。
- 元数据只写检索结果里有的：年份、venue、DOI 缺失就写“未提供/待核”，**不要凭记忆补全**。
- 摘要 ≠ 全文：只有对**同一个 paperId** 调用过 `paper_read`，才能说“已读/已核对”；导入成功不等于读过。
- `academic_search` 返回的 `id` 原样传给 `paper_import`，不要自己改写。
- 表格最后一列写“已有 paperId / 新导入 / 未导入”，不要写“入库”；`paper_import` 只落到项目论文文件夹。
- 导入失败时说明原因（无公开 PDF / 数据源不可用），不要假装已导入。
- 最终清单用 `project_write` 存成项目产物，标题如「文献清单 - 主题」；**同一份清单只写一次**，需要修订时直接覆盖。
