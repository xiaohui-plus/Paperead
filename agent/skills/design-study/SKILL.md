# 设计研究

目标：给出**能被审稿人和合作者直接评审**的方法学方案。

## 流程

1. `project_read` 确认研究问题；若项目没有明确问题，先用 `frame-question` 的思路收敛一个，再继续。
2. `library_search` 找 2-4 篇同类研究，提取它们的样本量、终点与统计方法作为参照。
3. 方案必须包含：
   - 研究类型与理由（观察性 / 干预性 / 回顾性 / 建模研究等）；
   - 研究对象、纳排标准、样本量估算依据；
   - 分组与对照（含阴性/阳性对照、盲法与随机化，如适用）；
   - 主要终点与次要终点（可测、有时间窗）；
   - 统计方法（效应量、检验、混杂调整、缺失值处理、多重比较）；
   - 偏倚控制与敏感性分析；
   - 伦理与数据合规要点。
4. 单独列「可行性风险」：数据可及性、样本招募、算力/实验条件、时间线依赖。
5. 用 `project_write` 存成产物「研究方案 - 主题」。

## 复现与配方

用户要对某篇工作做复现、复刻训练配方或核对论文与代码时，分三种情况写，不要混在一起：

- **复现规划**：列代码仓库、数据集、指标、运行环境、关键超参、成功判定。执行前先问清环境（本机 venv / Docker / 只要方案），得到答复再动手；没答复就只交付方案，状态写 `未执行`。
- **训练配方**：整理成表——任务、数据集（名称 + 规模 + 许可）、预处理、模型与规模、优化器/学习率/batch、训练步数与算力、评测集与指标、代码路径。查不到的字段写 `未公开`，不要填推测值。
- **论文-代码审计**：逐条核对论文主张与公开代码的默认配置、指标口径、数据处理是否一致，输出 `主张 | 代码位置 | 是否一致 | 影响`，并列出缺失代码、不可复现部分和复现风险（高/中/低）。只有实际看过代码或运行输出才写「一致」。

这三种产物都不是实验结果：没有真正跑过，就不能写「已验证」「复现成功」。

## 约束

- 不要给通用模板；每个小节都要落到当前问题。
- 样本量与统计方法要给依据，不要只写“待定”。
- 区分「必须做」和「有条件再做」，避免方案不可执行。
